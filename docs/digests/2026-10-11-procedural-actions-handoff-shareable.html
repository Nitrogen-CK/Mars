01 / orientation

What is here now

A game-agnostic action layer for rigid articulation with authored timing, observed transform settlement and identity-scoped observations.

AUTHOR

Phases and named motion

Clip assets contain body/limb keys, phase timing, windows and markers. The toolkit adds Details, phase/slot timeline, curves and transform-key controls.

RESOLVE

One transform publisher

Articulation settles kinematic ECS transforms. Jolt supplies clearance/contact queries. Body actions claim the body; disjoint limb actions can coexist. Borrowed walking limbs use gait protection, return and replant policy.

OBSERVE

Receipts, not guesses

Ordered per-action streams separate evaluated samples, accepted geometry, closed windows, terminal outcome and gaps. A copied debugger/editor view can show live settled pose without inventing receipts.

New and enhanced: existing gait, chain IK and body/surface positioning provide the base. This session adds reusable clips, an ActionPlayer and standalone appendages; it enhances ownership, gait withdrawal/return, lifecycle handling and observation. A body action is subject-exclusive; combine its body and limb choreography in one action. Independent limb-only actions may run together when their claims do not overlap.

04 / toolkit tour

Read the three modes literally

Current layout: Clip motion and Preview configuration Details on the left; mode/status toolbar, viewport, transport, timeline, curves and recording on the right.

01

Authored

Editable requested keys and guides. Select a phase and body/slot row before moving an endpoint or bend guide. Invalid drafts can be saved, but cannot Play until compilation is valid.

02

Solver

Disposable Game world, normal ECS/Jolt pipeline, at most one world tick per editor frame. Backward seek reseeds and replays; preparation and errors must remain visible.

03

Recorded

Copied accepted observations, stream provenance and gaps. After editing the source or Preview dependency, old geometry is hidden until a fresh recording; old metadata remains readable.

Viewport truth: requested guides and settled geometry are distinct. Lines between samples are display chords, not swept-collision proof. There is no Apply-to-selected-live-subject command.
Missing mesh or tiny part
Check the matching Preview asset and Appearance fields. LimbNod’s terminal Cube binding lives under Subject → Bindings → LimbBindings → Appearance → PreviewMesh. Visual scale does not change solver geometry.
Play disabled or Solver not ready
Read the clip diagnostics, matching Preview selection, slot binding and world status. Saving a draft does not assert that runtime admission will succeed.
Gizmo or key does not move
Return to Authored, select the phase/track/key, then use its endpoint or bend handle. Solver and Recorded are observation modes.
Recorded geometry disappears after editing
The older recording has stale source provenance. Its metadata remains for inspection; run Solver again to obtain geometry for the new revision.

There is no separate Validate button, Rate/Loop control set, or live-subject Apply button in this implementation.

05 / authoring route

Make a clip of your own

Build the authored action first, then the disposable subject used to inspect it.

Content Browser → Animation → Procedural Action Clip. Create its sibling Preview Config from the toolkit or select an existing _Preview_DA. Save both assets separately.

Set finite phases and durations. Add body keys and/or named limb slots, then endpoint, orientation and bend keys. Add markers and windows where gameplay needs boundaries.

In Preview Details, define topology and real part bindings, floor/obstacles and appearance. Set preview-only action tuning here; the clip does not own mesh choices.

Scrub in Authored, run Solver, read status and Recorded observations, then edit and replay. A saved invalid draft is recoverable; it is not a valid playable clip.

06 / integration

Request motion; observe settlement

Keep action scope, player and identity distinct. Request completion, evaluated sample and accepted pose mean different things.

MANAGED CLIP

Compose, bind, create

Compose subject transform parts, Articulation and ActionPlayer. Keep an action scope alive. Bind Nod → NodArm in the separate AngelScript runtime fixture; the shipped LimbNod Preview binds Nod → InspectionArm. For already resident content use Create_FromLoadedClip(ActionScope, Player, LoadedPlaySpec); soft-path Create_FromClip admits after load. Managed playback advances its own timeline and ends normally at clip completion.

Validate_Data checks resident data; Get_AdmissionReport is advisory and does not reserve resources. A returned handle begins pending, not accepted.

MANUAL INPUT

Submit, End or Cancel

Use Create_Manual and wait for Ready; Playing is the managed-clip state. Submit a Request_SubmitPoseBatch containing every claimed channel. A partial batch rejects; a second batch while one is unsettled is busy. Wait for its accepted receipt before advancing dependent gameplay. Then use Request_End for normal completion or Request_Cancel to interrupt. Game-owned manual windows must be managed by the game; framework clip markers/windows are authored clip content.

Cancellation closes action windows before return. A terminal result reports the outcome and recovery; after draining and acknowledging it, Request_Release releases a still-live action instance. Managed clips finish their timeline or are interrupted with Cancel; End is the normal manual-only exit.

Terminal receipt and limb return/recovery are separate. After action-scope loss retain Player + Identity to drain the retained stream, without dereferencing a dead handle.

Consumption rule: one designated consumer acknowledges each identity stream. Advance by StreamSequence, not sample sequence. Handle gaps and StreamExpired. Evaluated samples are not contact-certified poses, and a successful request callback is not accepted geometry.

07 / game boundary

Crawler body jab remains game-owned

The existing body-jab encounter uses the manual action adapter while preserving the game’s phase clock and targeting authority.

Enable and inspect

Use single-player PIE with a crawler in Sandbox. The actual switch is Spec.Combat.Enabled; StartAggressive controls initial aggression. DebugDrawAttack shows accepted hit centres. Windup is yellow, Strike red, Recover/CancelRecover blue. The white crawler-to-centre guide is visual evidence, not a collision result.

Observe: approach, watch anticipation → strike → recovery → cooldown, then dodge during anticipation and try a wall between crawler and target. Check the existing jab stays readable and returns to a usable state. Where health feedback is observable, one strike should damage a target at most once.

Crawler game code owns target/hurtbox relationships, collision ordering and damage. Framework receipts carry motion evidence.

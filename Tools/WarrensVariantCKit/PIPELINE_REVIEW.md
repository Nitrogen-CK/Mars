# Variant C production pipeline review

2026-10-24. Read-only audit of existing production code, catalogs, source JSON and native reference images. No Unreal/Blender invocation or editor mutation. Recommendations below are proposed implementation, not runtime acceptance.

## Recommendation

Use **quiet component material overrides on the exact retained source geometry across all eleven tiles and every elevation** as the complete base pass. Add the reusable art families over that base only where their visual thickness fits. This is the smallest way to remove remaining prototype grid faces without inventing walls, sealing openings, changing level geometry or altering collision.

The current adjacent-floor veneer algorithm is useful for interior detail but is not a complete whole-level surface extractor. Extending its rectangle and height range alone will not cover the tall Belfry, exterior rock skirts, floorless shaft faces or every stacked underside.

## Complete base coverage without changing shape

1. Capture the eleven tile packages plus the persistent assembly separately. Preserve original component slot paths, actor/component identity, source mesh, instance transforms, collision settings, visibility and package backup/hash. Do not use the already-dressed appearance as the original rollback state; retain both original and pre-pass snapshots.
2. Match source-owned geometry components against a baseline whitelist, including generated material-group suffixes. Override **component material slots**, never the shared `/Engine/BasicShapes/Cube` mesh material. Start with floor/ramp to quiet floor stone and wall/roof to quiet masonry; explicit mappings handle retained rock/root/pier/gallery/grate geometry. Keep water on its separate depth-appropriate recipe. Unclassified source kinds must be reported, not silently flattened to stone.
3. Keep source mesh, transform, instance count/order, collision profile, trace responses, overlap behavior, mobility, tags and entity data byte-for-byte or field-for-field unchanged. Do not hide source collision actors merely to remove a grid texture.
4. Remove no older kit actors indiscriminately. Existing CCK/PWC ownership remains separate; one new base-pass ledger owns only its component overrides. Coordinate with the old CCK pass: its reapply restores old baseline materials before overriding WaterworksW, so running it after a new whole-level pass can undo the base coat ([unreal_scenes.py:157](/D:/Repositories/CkRepos/Orion/Tools/ChainCrossingKit/unreal_scenes.py:157)). Define a single material-override owner/order.
5. Rollback restores recorded component slots and visibility, then removes only the new owner's dressing. Package backups remain the recovery for interrupted saves. A successful rerun must reproduce the same overrides and instance set.

Source HISM grouping uses `(kind, material path, collision profile)`, and alternate groups receive a hashed suffix; an exact actor label such as `Warrens_Greybox_wall` does not enumerate every source wall group ([build_warrens.py:1338](/D:/Repositories/CkRepos/Orion/Tools/LevelDesign/anchor_plans/build_warrens.py:1338), [build_warrens.py:2624](/D:/Repositories/CkRepos/Orion/Tools/LevelDesign/anchor_plans/build_warrens.py:2624)). Match the saved component/source provenance, not only an unsuffixed label.

If a material override is genuinely unavailable, the fallback is a render-only duplicate of the **actual source mesh and full component/instance transforms**, with new quiet slots and `NoCollision`; hide only the original render component after verifying collision/trace behavior. Do not place a same-volume visible duplicate over a visible original: coincident surfaces will fight. This fallback adds ownership/visibility complexity and should not be the default. Exact copies preserve shape; coarse room-sized replacement boxes do not.

## Minimal reusable production extension

Reuse the current Blender primitives, material loader, FBX exporter and importer; add a thin new catalog driver and a shared registry instead of a third independent implementation. The global catalog has 150 entries, one (`I14`) explicitly reuses the existing key, and several global parts already have CCS/PWC equivalents. Maintain `catalog ID -> production mesh + pivot/dimensions adapter` entries with reviewed equivalence; do not claim all 150 are unique new models or assume equal names mean identical fit.

The existing core needs a small explicit schema adaptation before direct global-catalog use:

- `Builder` seeds with `int(id[3:])`; IDs such as `A01` and `H07` fail. Use a stable full-ID digest, read dimensions by explicit width/depth/height keys, and give new IDs explicit pivots/categories ([build_kit.py:61](/D:/Repositories/CkRepos/Orion/Tools/ChainCrossingKit/build_kit.py:61)). Preserve old-kit behavior while adapting the new family.
- `finish()` parses the same numeric suffix, guesses pivot/category from CCS numbers, normalizes every axis to the catalog envelope, joins every primitive and writes `part['blender_brief']` ([build_kit.py:143](/D:/Repositories/CkRepos/Orion/Tools/ChainCrossingKit/build_kit.py:143)). Global entries use `blender_generation_brief`, descriptive pivots and lowercase category names. Normalize the schema explicitly. Do not independently normalize joined mechanism subparts: pivot-relative socket locations would move. Support a declared source-authored pivot/fit policy, not a global bounding-box recenter.
- Export static subparts as separate registry entries where the catalog/recipe requires independent movement: bell shell/yoke/clapper; hoist drum/hook/cage; sarcophagus body/lid; vat/lid; dial blanks; door/leaf vs frame. Static fixed crate stacks may merge. Current collection join is valid only within one intended moving/static part.
- Current UV0 projection is physical-scale tiling, except AT01 samples one fixed swatch, and no UV1 is generated ([build_kit.py:162](/D:/Repositories/CkRepos/Orion/Tools/ChainCrossingKit/build_kit.py:162)). Add explicit atlas-cell/trim-lane selection for glyphs/banners/plaque faces; do not feed them through generic projection. UV1 is conditional on actual static-light requirements, not automatic claim.
- Keep FBX centimeters and established `(X,-Y,Z)` conversion. Importer now checks `convert_scene=true`, `force_front_x_axis=false` and records imported front +Y / mechanism yaw -90° ([import_assets.py:304](/D:/Repositories/CkRepos/Orion/Tools/ChainCrossingKit/import_assets.py:304)). Pivot/axis claims need asymmetric landmarks or socket probes, not symmetric bounds alone.
- Keep ownership/source-path/hash guards and material-slot matching by names; these are already implemented ([import_assets.py:39](/D:/Repositories/CkRepos/Orion/Tools/ChainCrossingKit/import_assets.py:39), [import_assets.py:309](/D:/Repositories/CkRepos/Orion/Tools/ChainCrossingKit/import_assets.py:309)). Cache on FBX plus generator/schema/material recipe revision, and keep the shared material namespace explicit as PWC already does ([import_assets.py:5](/D:/Repositories/CkRepos/Orion/Tools/PumpCisternKit/import_assets.py:5)).
- Group Unreal HISM rows by mesh plus material overrides/render settings, not ID alone. Current `add_instances()` groups only by ID and applies the first row's material override to the whole group ([unreal_scenes.py:51](/D:/Repositories/CkRepos/Orion/Tools/ChainCrossingKit/unreal_scenes.py:51)); heterogeneous same-mesh rows would receive the wrong material. Moving actor skins stay under their existing visual nodes rather than static HISM batches.

## Integration gates

Before live placement, require catalog dispatch completeness/reuse accounting, finite geometry, valid triangles/normals, hollow openings, pivot/socket landmarks, material keys, packed textures, physical UV scale, actual bounds and imported centimeter/axis checks. Existing validators verify saved bounds/UV presence and counts, but general open-mouth/clearance/shape checks need family-specific evidence ([validate_blender.py:12](/D:/Repositories/CkRepos/Orion/Tools/ChainCrossingKit/validate_blender.py:12)).

After each tile: compare source actor/component/instance transforms and collision/trace settings against its captured baseline; only owned art and declared material/lighting changes may differ. Review real player-camera views at every occupied Z band: Pit/Undercroft, Cistern/tunnels, main floor, Ossuary/Reliquary/loft, Mill and high Belfry. Include stairs/ramp mouths, all source windows/view rays, water banks, gate travel, ladder hands/pack clearance, and dark lantern readability. The source declares upper top 24m and tall rooms ([warrens_v8c.json:1835](/D:/Repositories/CkRepos/Orion/Tools/LevelDesign/anchor_plans/data/warrens_v8c.json:1835)); a single ground-level flythrough is insufficient.

Run the relevant source-manifest/movement checks and focused UnrealToolbox gates when integration changes require them. Editor and PIE observations remain separate from packaged Level Instance collision/network claims. This document gathered source evidence only; no test, render or live coverage success is asserted.

# Production gates

1. Source audit and rollback: snapshot all 11 current tile packages; retain earlier undressed four-tile baselines. Resolve every source room, dressing proxy, puzzle location, ramp, port and protected view to authoritative data. Verify exact source actor/instance inventory and report existing art/topology mismatches.
2. Art coverage: reconcile the 150-entry art catalog and existing Chain/Pump assets. Inspect model sheets and district concepts; generate missing visual directions/sheets only where a real gap remains. Every required model resolves to an asset/reuse and a meaningful Blender brief. Picture labels do not override IDs in written catalogs.
3. Procedural asset production: generate missing architecture, terrain/water, hero machinery/bells, burial/organic and supporting prop families through shared headless Blender tools. Verify real saved meshes, pivots, axes, UVs, named materials, bounds, hollows/openings and packed libraries. Review silhouettes against actual references.
4. Full-level candidate: fit structural art to all saved source surfaces at all elevations; build room-appropriate assemblies with no visual port/sightline blockage. Provide source-fitted cutaways and area review views before live application. Retain existing working Chain/Pump art, correct gaps and unify material continuity.
5. Unreal production: import only owned assets, create kit/diorama maps, apply tagged NoCollision instances to each original tile. Original source mesh/transform/collision and active gameplay stay authoritative. Source-wide quiet material overrides are now allowed on all Variant C source tiles; this removes exposed foundation/upper-side grid artifacts without inventing shell geometry.
6. Whole-level acceptance: saved-state audit against all original tiles, per-room and transition PIE views, protected-view/clearance review, focused Toolbox automation and final adversarial audit. Fix findings, rerun affected gates on the final artifacts, publish a local evidence-linked preview. No commit/push.

Each gate records observations and branch decisions in PROGRESS.md. Visual failures trigger source-grounded placement/material fixes, not silent topology changes. A mismatch needing gameplay or route redesign is recorded explicitly rather than fabricated away.

# Cookbook without BookMenu

The active `StylizedR02` cookbook uses `UCk_UserWidget_UE` for all six page widgets and `utils_widget_rasterizer::RenderWidgetToTexture` for cached `UTexture2D` page images. Rendering is client-only, uses the rasterizer's capability check, and uses `GammaCorrection::Disabled` for its sRGB target. Page widgets and textures remain referenced by the presentation until the item is released; material cleanup restores the original materials.

The existing mesh, skeleton, clips, materials, widgets, input and physical-item code are independent of BookMenu. CkFoundation (`CkUICore` and `CkWidgets`) and Unreal UMG/Slate remain required. The project plugin entry was deliberately left enabled.

- The rendered editor remains plugin-enabled. The plugin-disabled test processes use NullRHI; those tests prove script/gameplay independence, not rendering. The asset audit and actual renderer observations supply the separate UI evidence.

## Before removing the plugin project-wide

Nine older prototype assets outside `StylizedR02` still depend on plugin assets. The exact package/dependency list is `widget_migration.json` under `remaining_prototype_dependencies`: `SK_Book_Worn` and eight `PlayerCookbook_*` materials/material instances. These assets were left untouched. Retire or migrate them after checking their referencers; this is separate from the live cookbook.

The older art scripts directly under `Tools/BookMenuArt/` also target the old plugin assets. Keep those only as historical tooling if the plugin is removed. The current `StylizedR02` import/migration tools do not require BookMenu APIs.

After resolving the prototype assets, disable/remove the `BookMenu` entry from `Mars.uproject` and remove its plugin directory when desired. Use UnrealToolbox for the editor build and focused tests. No plugin removal, prototype deletion, commit or push was performed in this revision.

# Mise crypt making-of: Blender shots

Footage: `D:\Repo\Content\Devlog\mise_crypt\blender\<shot>\%05d.png` (1920x1080 PNG, 30 fps, clean, no text) with
`shot.json` (frames, stages with start/end frames, real_seconds_covered, steps) and `_preview.mp4`.

Re-run (headless, one Blender process, about 9 minutes for all 11 shots):

```
"C:\Program Files\Blender Foundation\Blender 5.2\blender.exe" -b --factory-startup ^
  --python D:\Repo\Mars\Tools\Devlog\footage\blender\devlog_crypt_shots.py -- ^
  --shot all --out D:\Repo\Content\Devlog\mise_crypt\blender
```
`--shot a,b` renders a subset. `--draft` renders 960x540, every 4th frame. `--sample N` renders N spot frames plus every stage start.

How it was made: the kit was never screen-recorded, so the builders are replayed. Every primitive a crypt
piece adds goes through `geo.Builder.emit`. The script wraps that call (monkeypatch, the add-on is untouched)
and tags every face with the primitive that made it. A geometry-nodes reveal then shows the build one primitive
at a time, each block dropping in. The blockout is the same build with bevel and tilt/jitter switched off and the
same random sequence, so the course layout is identical. See the docstrings of `devlog_crypt_shots.py` and `dl_replay.py`.

`real_seconds_covered` is the time the real procedure takes on this machine: about 0.03 s per piece build and map,
6.5 s for the atlas at 256 px/m, 0.01 s for the room plan. For the library showcases (pier_family, kit_lineup) it is 0.
That is the point of the timelapse: the code does in milliseconds what the footage shows over seconds.

Caption ideas are max 7 words per line, 2 lines.
